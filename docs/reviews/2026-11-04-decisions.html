Onboarding without a terminal

A maintainer onboards a repository with /factory:init without opening a terminal: every question is asked once, up front, the config and baseline are written once on the confirmed paths, and every protected write and the onboarding commit is an approval prompt.

12acceptance criteria, 5 of them negative cases
4decisions, all confirmed by @ishpr
5dogfood findings closed: #57, #58, #63, #64, #65
Highrisk tier: changes the commit guard

Why this work

Onboarding Lathe onto itself took two hand-run terminal scripts: the detected code paths missed most of the plugin, the paths were confirmed only after the config and baseline were written, protected files had to be copied in by hand, and the onboarding commit was refused outright. Each of those became a finding; this contract closes them so the next onboarding is answers and approvals only.

Decisions

Docs ship with the fix, so they never drift from the code. Decided by @ishpr
D2 Which directories count as a Python project's code?
Any dir with .pyPackages + scriptsPackages only, ask
Finds scripts, hooks and lib on Lathe; tests, docs, fixtures, examples, templates and build output stay out. Decided by @ishpr
D3 What happens to an onboarding-only commit that has no verify stamp?
Ask, flag workflowsAsk, no workflowsKeep refusing
A human approves it in a prompt that lists every file and marks the CI workflows and other files the edit guard does not protect. Unattended runs still refuse, and any commit that touches code or tests still needs a stamp. Decided by @ishpr
D4 How do the confirmed paths reach init?
Repeatable flagsOne JSON file
The values are visible in the command the human approves. Decided by @ishpr

In scope

  • Code-path detection that finds every source directory (#57)
  • Paths asked before anything is written, then passed as flags (#58)
  • Default high-risk paths that match nothing are dropped and named (#64)
  • The CLAUDE.md agreement names only paths that exist and is checked (#65)
  • Protected files written through approval prompts; the baseline and the onboarding commit go through approvals too (#63)
  • Version 1.0.7 with its changelog and install docs

Out of scope

  • The maturity and security assessment fixes (#59 to #62): their own increment
  • Re-onboarding Lathe and the sample app: the next step after this ships
  • Any path that lets a commit through without a stamp or a human's approval
  • The edit guard and its list of always-protected files

How it will be shown to work

  • Tests for all 12 criteria, written first and frozen, then green in verify
  • The full suite green and no new quality violations against the recorded baseline
  • A dry run of init on Lathe, showing the four code directories, the dropped high-risk paths and the CLAUDE.md check result
  • The guard's approval prompt for an onboarding-only commit, showing the file list and the marked files
