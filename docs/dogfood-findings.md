# Dogfooding findings: lathe onboarded with its own factory

Factory 0.6.0, installed from the `lathe` marketplace at local scope, onboarding this repository
with `/factory:init` on branch `chore/onboard-factory`, while four git worktrees of the same repo
(`lathe-rebase`, `lathe-measure`, `lathe-perms`, `lathe-approve`) carry parallel work. Each row is
a gap the product showed on itself; each gets a fix or a decision.

| # | Where | What happened | Fix |
|---|---|---|---|
| 1 | init, stack detection | A monorepo with no stack marker at the root (`plugins/factory/pyproject.toml`, `examples/sample-app/pyproject.toml`) gets "no stack marker found"; the human must pass `--stack`. | Detect stack markers one level down and offer them, or accept a `--root-project` path. |
| 2 | init, paths | `--stack python` writes the stack's defaults (`app/**`, `src/**`, `tests/**`, `app/main.py`, `alembic/**`), none of which exist here. | Derive paths from the project that holds the marker; never write paths that do not exist without saying so. |
| 3 | sandbox, worktrees | The sandbox init installs allows writes only to the current checkout, so sibling worktrees became unwritable mid-run and two agents stopped. The human had to list each worktree in `settings.local.json`. | Put worktrees under a gitignored `.claude/worktrees/` (the sandbox's `.` then covers them), and have init add any existing `git worktree list` paths to `allowWrite`. |
| 4 | tools | The ratchet calls `python3 -m ruff` / `python3 -m mypy` on the system interpreter, which a sandboxed session cannot install into. | Run tools from the project's own environment (`uv run`, the stack's runner) or `uvx`, recorded in `tool_versions`. |
| 5 | commit guard, worktrees | The commit guard demanded a verify stamp for a commit made in another worktree, judged from the session's repo. | Resolve the root from the command's own working directory (`git -C` / `cd` target), per worktree. |
| 6 | sandbox, temp dirs | The eval harness and `check_examples.sh` could not use their temp directories. | Use `$TMPDIR`, which the sandbox allows. |
| 7 | Bash guard | A false match blocked the permission-check command. | Find the matching rule and narrow it; add the command as a test case. |
| 8 | lint | A global, strict `ruff` config on the machine leaks into the plugin's lint and flags old code. | Pass the project's config explicitly (`--config` / `--isolated` where intended). |
| 9 | Bash guard | A read-only inline script that opened `.claude/sdlc.json` was refused as an edit. | Distinguish reads from writes (open mode, a write call) before refusing. |
| 10 | init, settings | The allow rules init writes pin the plugin cache path with its version (`…/factory/0.6.0/scripts/*`), so they stop matching after an update. | Use `${CLAUDE_PLUGIN_ROOT}` or a version wildcard (`…/factory/*/scripts/*`). |
| 11 | evals | Evals started inside a sandboxed session fail every run with EPERM (nested `claude` cannot write `~/.claude`), and the harness wrote an all-zero baseline and exited 0. | The harness refuses a baseline with unstarted runs; evals are documented as run from a normal terminal. |
| 12 | init, baseline | On a rerun, the sandbox init installed forbids writing `.claude/baseline.json` (by design), so init crashed with a traceback in `ratchet.py`. | When the baseline cannot be written, print the exact human command to record it instead of a traceback. |
| 13 | graph schema | The database reports schema 010 while factory 0.6.0 ships migration 011; init and index never brought it up to date, so the Foldkit edge kinds are missing. | `graph status` reports "behind by N migrations"; init (and `factory:graph`) applies pending migrations, which are idempotent. |
| 14 | maturity, monorepo | "No dependency manifest found": the manifests sit in `plugins/factory/` and `examples/sample-app/`. | Look for manifests under the configured app paths, not only the root. |
| 15 | maturity and secrets scan | The deliberate fake AWS keys in the guard's own tests count as committed secrets. | A fixture marker (an allow-list of known test keys, e.g. AWS's documented example key, or a `# secret: test-fixture` comment). |
| 16 | ratchet scope | The ratchet scans `plugins/factory/.demo/app-venv`, a vendored virtualenv: hundreds of third-party findings, and output truncated at about 20,000 characters for every auditor. | Skip virtualenvs and gitignored paths by default; summarise by check when output is large. |
| 17 | agents | The `factory:auditor` agents reported their Grep and Glob tools unavailable though the definition lists them, and fell back to shell `grep`/`find`. | Find why the declared tools are missing (tool names, the session's tool set) and add a test that each agent's declared tools resolve. |
| 18 | dead-code checker | One entry module (`mcp_server.py`) is configured, so every hook, script and the CLI reads as "never imported": hundreds of false findings that also inflate the security report's "unmounted code" count. | `entry_modules` takes a list including `hooks.json`-registered hooks, console scripts from `pyproject.toml` and `scripts/*`. |
| 19 | env-read checker | It expects one config module and flags even `orchestrator/config.py`. | Accept a list of config modules; treat command-line scripts as allowed. |
| 20 | module-state checker | Constant lookup tables written as `set()` are flagged as per-process state. | Treat module-level sets never mutated as constants, or suggest `frozenset`. |
| 21 | security assessor | "Blast radius not computed: neither the graph MCP nor the CLI was available", minutes after the graph was indexed. | Give the security subagent the CLI path it needs, or pass `graph_impact` results in its brief (`--impact`). |
| 22 | security report | "146 findings in code nothing mounts or imports" is mostly finding #18's false positives. | Fixed with #18; until then, label the count as unverified. |
| 23 | graph impact | Hooks and scripts are tested through subprocess calls the graph cannot follow, so `graph_impact` reports 0 tests for them and cannot order work. | Extract `subprocess.run([... "hooks/x.py" ...])` and `python3 -I scripts/x.py` call sites in tests as `tests` edges. |
| 25 | init, CI templates | Init installs `sdlc-claude-review.yml` by default, the workflow the security review flagged: it runs on `pull_request` with `ANTHROPIC_API_KEY` and `id-token: write`, so a same-repo branch PR could edit it and read the key. Left out of lathe's onboarding. | Run the review from the base branch's definition (`pull_request_target` with no PR code executed, or `workflow_run`), as the evidence job does since 0.6.0; install it only once fixed. |
| 26 | verify, commit guard | `/factory:verify` and the commit guard assume every commit belongs to a contract; onboarding (and any change not born from a ticket: docs, config, the factory's own setup) has none, so the skill's contract steps do not apply and the path to a stamp is unclear. | A contract-less verify mode: tests, ratchet, secret and agent-config scans, no acceptance or scope; the stamp records `contract: none`. |
| 27 | init, gitignore | `.claude/work/handoffs.md` and `.claude/work/spawns.json` (local hand-off and spawn logs) are not covered by the `.gitignore` lines init adds, so they show as files to commit. | Ignore `.claude/work/*` except `README.md`. |
| 28 | init, PR size | The onboarding PR (42 new files, a 97 KB baseline) fails the 1,000-line size check of the gate it adds, which runs on that same PR. | Init writes `pr_size.exclude` with the files it generates (`.claude/baseline.json`, `docs/reviews/**`), so its own PR and every baseline refresh are measured on hand-written lines only. |
| 29 | init, CI gate | The generated `sdlc-gate.yml` runs `pytest` at the repo root with nothing installed and no Postgres service, and its route sweep starts `uvicorn app.main:app`: on a monorepo or a repo with no HTTP app the required check can never pass. | The gate runs `commands.test` and installs the project (or projects) the configured paths name; the route sweep and route checkers are written only when routes were detected. |
| 30 | init, CI gate | The gate never installs the project, so `pip-audit` and `pip-licenses` inspect only the runner's tools, and the ratchet runs without the project's dependencies; `tool_versions` is empty, so CI installs whatever ruff and mypy are newest. | Install the project before the audits; record the local ruff/mypy versions in `tool_versions` at init. |
| 31 | baseline | The baseline holds 384 keys from gitignored virtualenvs (`.venv`, `.demo/app-venv`), which CI never has: the headline counts are inflated and cannot be re-recorded by an agent. | Same fix as #16 (skip virtualenvs and gitignored paths), then a human re-records. |
| 32 | init, licence allow-list | The template's exception names `psycopg2-binary` with "approved by: to be named", not the package this repo uses and against the file's own approver rule. | Ship the allow-list with no exceptions; init adds exceptions only from the installed environment, unapproved and marked as such. |
| 33 | init, generated docs | `CLAUDE.md`, `REVIEW.md`, the rules, the PR template and `docs/db-roles.sql` describe a FastAPI and alembic service (route auth, `APIRouter`, `appdb`, a second code owner with no CODEOWNERS) and miss this repo's real risk surface (the OIDC trust path, the hooks, the CI templates). | Generate from what was detected: route rules only when routes exist, migrations only when a migrate tool is found, the real test command, and a REVIEW.md listing the configured `tier_high_paths`. |
| 34 | init, dependabot | The pip ecosystem is configured at `/`, where there is no manifest. | One entry per directory that holds a manifest. |
| 35 | init, project settings | `.claude/settings.json` does not register the marketplace or plugin, so a fresh clone gets the rules text with no hooks; its allow list is the generic multi-stack template (npm, cargo, go, poetry) and lacks the configured `uv run --project ...` test command. | Register `extraKnownMarketplaces` and `enabledPlugins`; trim the allow list to the detected stack and allow `commands.test` exactly. |
| 36 | sandbox, worktrees | Worktrees inside the repo fail too: `git worktree add .worktrees/x` dies with "unable to create file plugins/factory/.mcp.json: Operation not permitted", because the sandbox forbids creating `.mcp.json` (and other agent-config files) anywhere, and checking out a branch writes them. | Worktrees are created by a script run outside the sandbox (or by the human), which then adds the path to `allowWrite`; document that agents cannot create checkouts under the sandbox. |
| 37 | guards, human-owned files | Every human-owned change (the baseline, `sdlc.json`, sandbox settings) meant the human copying a command into another terminal. The decision must stay human (an agent that loosens its own constraints has none), but the typing need not. | Interactive sessions: the guards answer `ask` (Claude Code shows the exact change; one approval applies it) instead of `deny`; unattended runs still deny and escalate; durable policy changes go through a PR that CODEOWNERS routes to a human. Claude Code's `!` prefix is not a way around this: probed 2026-11-04, a `!` command runs inside the same sandbox, so it cannot do a sandbox-blocked step either. The exact human-only commands (ratchet `--update`, freeze `--unfreeze`, `git worktree add`) are therefore listed in `sandbox.excludedCommands` and gated by the guard's `ask`. |
| 38 | plugin updates | Updating factory takes two commands (`claude plugin marketplace update lathe`, then `claude plugin update factory@lathe`), and neither can run inside a factory session: the sandbox it installs blocks writes to `~/.claude/plugins`, so the session cannot upgrade its own plugin. | Recommend the marketplace's auto-update in the install docs and in init's closing lines (Claude Code updates outside the sandbox; the human only runs `/reload-plugins`); keep the one-line manual form for a normal terminal. |
| 39 | post-edit formatter | After a small edit, the post-edit hook ran `ruff format` on the whole file (`guard_edit.py`, `lib/sdlc.py`), turning a few changed lines into a whole-file diff; two agents editing `lib/sdlc.py` in parallel then conflict across the file. | Format only files that were already formatted (check first with `ruff format --check`), or only the changed range; never reformat legacy code as a side effect of an unrelated edit. |
| 40 | tests | `test_autonomy_review.py` asserts the word "worktree" is absent from the output, so it fails whenever the checkout itself lives under a `.worktrees/` path. | Assert on the message, not on any occurrence of the word (strip the checkout path first). |
| 41 | bootstrap | Fixing the guards while the installed (older) guards enforce: the 0.6.0 Bash guard refuses commands that merely mention protected files (so `check_skill_permissions` cannot run), and its commit guard judges every worktree's commit by the session's checkout (#5), so the fixes cannot be committed under it. | A documented upgrade path for the factory's own repository: develop the plugin with the installed copy disabled for that repo (or pinned to the version under development via `--plugin-dir`), and dogfood the new version after it is installed. |
| 42 | spawn guard, routing | The six fix agents were requested as three Opus and three Sonnet; the 0.6.0 spawn guard classified all as stage `implement` (executor tier) and rewrote the three Opus requests to Sonnet (`.claude/work/spawns.json`: requested `opus`, model `sonnet`). The orchestrator's deliberate choice was overridden, which is the behaviour DESIGN §18 step 2 removes. Separately, whole-area briefs left expensive agents waiting on long test runs. | §18 step 2: the guard records the choice and enforces only cost ceilings. And split work by tier at the orchestrator (subagents cannot spawn subagents): Opus for judgment, Sonnet for implementation, Haiku for test runs, triage and search. |
| 43 | stalled runs | Seven agents each ran both full suites at once on one machine and one Postgres (5–6 min alone, 20+ min together), piped through `tail` so no output appeared until the end; 10-minute monitors expired and re-armed in loops while Opus- and Sonnet-tier agents waited. | Impact-narrowed tests while working, the full suite once at the gate; a machine-wide cap on concurrent heavy suites; streamed progress (a JUnit or progress file), with a stall defined as no new output for N minutes; test runs as background jobs the orchestrator is notified about, failures triaged on Haiku; a time budget in every brief; a database per worktree created automatically. |
| 44 | run_headless.sh, sandbox | `run_headless.sh` dies under the sandbox writing `/dev/fd/62` ("Operation not permitted"): it uses process substitution, which the sandbox refuses, so the seven `test_run_headless_*` tests fail in any sandboxed session. | Replace process substitution with temp files under `$TMPDIR` (or pipes); a test runs the script under the sandbox profile. |
| 45 | Spanner tests, sandbox | Under the sandbox, the Spanner emulator check (`emulator_smoke._reachable`, a bare TCP connect to localhost:9110) passes because something listens there, but the gRPC calls then hang until the test's 300 s timeout; one such test stalled the whole graph suite (and `verify.py`, 50 minutes with no output). Likely cause, not confirmed: gRPC sends localhost traffic through the sandbox's HTTP proxy (the proxy variables are set). | Probe with a real gRPC or REST call and a short deadline instead of a TCP connect; set `no_proxy=localhost,127.0.0.1` (or `grpc.enable_http_proxy=0`) for emulator clients; give emulator tests a per-test timeout well under the suite's stall budget. |
| 46 | orchestrator, sandbox | The orchestrator's process-identity check shells out to `ps`, which the sandbox blocks, so `test_a_recycled_pid_is_not_the_executor_and_is_never_killed` fails (TypeError on a `None` identity) in any sandboxed session, and the real watchdog cannot tell its executor from a recycled pid there. | Read process identity without `ps` (`/proc` on Linux, `psutil`-free `os.kill(pid, 0)` plus a start-time file the dispatcher writes), and fail closed (never kill) when identity is unknown. |
| 47 | sandbox, git push | `git push` from a sandboxed session fails ("could not read Username for 'https://github.com'"): the credential helper's keychain and `~/.config/gh` are outside the sandbox, so `/factory:ship` cannot push and a human pushes from a terminal. `gh` works because it is in `excludedCommands`. | Add the exact push form the skills use (`git push -u origin HEAD`) to `excludedCommands`, gated by the guard's `ask` interactively and denied unattended, like the other human-only commands. Tried mid-session on 2026-11-04 and it did not work: the git credential helper is `gh auth git-credential`, so the push spawns `gh` inside git, and an excluded parent does not obviously un-sandbox that child; nor is it clear the sandbox settings reload without restarting the session. The fix must be verified in a fresh session, possibly by pushing through `gh` itself or with a credential helper that runs outside the sandbox. |
| 48 | sandbox, excludedCommands | `gh *` in `excludedCommands` matched a one-line `gh pr list` but not a `gh pr create` with a multi-line `--body`, nor any line that starts with `cd … &&`: those ran sandboxed and failed reading `~/.config/gh`. | Skills pass PR bodies with `--body-file` (written under `$TMPDIR` or `.sdlc-stage/`) and run `gh` as the first word on its own line; the ship skill already writes a body file, so check every `gh` call in skills and agents follows that form. |
| 49 | GitHub ruleset, PR branches | A repository ruleset with the pull-request rule targeting all branches (`~ALL`) refused the push of a PR branch (`GH013: Changes must be made through a pull request`), so no PR could be updated. Found 2026-11-04 when the owner added rulesets. | Target the default branch only (`~DEFAULT_BRANCH` or `refs/heads/main`) for the pull-request, deletion and force-push rules; a second ruleset on all branches may block force pushes only. The settings template's comment says so; the admin setup should say it where it tells a team to protect the branch. With the default branch protected on the server, ship's exact push form can leave the sandbox (#47). |
| 50 | headless init, workspace trust | A headless `claude -p "/factory:init --headless"` in a freshly cloned, never-trusted folder ignored the 110 allow rules init had just written ("this workspace has not been trusted"), so `graph_impact` and one auditor command were denied; init recorded them under Failures and finished. Found in the cadence rehearsal, 2026-11-04 (6 min 56 s). | An unattended init needs the folder trusted first: one interactive start in it, or pass `--allowedTools`. Interactive runs are unaffected; docs/install.md has no troubleshooting section in this tree, so the note lives here. |
| 24 | graph impact | `graph_impact` on a shared fixture returned 378,000 characters (343 symbols, 554 tests) with no cap. | Cap the result, add a `counts_only` mode, and say when a file reaches the whole suite. |
